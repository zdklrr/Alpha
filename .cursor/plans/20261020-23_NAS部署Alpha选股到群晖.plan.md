## 风险与回滚

- **镜像体积**：torch CPU + 依赖约 1.5–2GB，`/volume1` 剩余 2.5T，无压力。
- **SQLite 数据损坏**：SQLite 位于 ext4 命名卷 `alpha_data`（非 bind mount），规避 WAL 页损坏风险；
  覆盖库文件必须在容器停止状态下进行。
- **回滚**：容器用 `restart: unless-stopped`；出问题执行
  `docker compose -f docker-compose.yml down` 即可停服，数据仍在 `alpha_data` 卷里；
  需要回退代码则把 `/volume1/docker/Alpha` 里的 `app/ strategy/` 换回旧版本并 `up -d --build`。
- **账号权限**：当前用 `sudo -S` 提权执行 docker；DSM 上 `江流儿` 属于 administrators 组。

## 关键决策记录

1. **用 CLI docker compose 而非 DSM「项目」UI**：UI 建项目会和已存在的 `container_name: alpha` 冲突；
   同时把 NAS 版 compose 复制成 `docker-compose.yml`，让用户后续在 UI 里也能接管。
2. **迁移本机数据库而不是让 NAS 重新同步**：NAS 出口直连行情源正常，但全量同步要 17 分钟且
   依赖腾讯源限速；`docker cp` 覆盖只要 1 分钟。
3. **`deploy-nas.sh` 增强**：自动补 `PATH`（sudo 下 docker 在 `/usr/local/bin`）、
   自动 `mkdir -p logs`（bind mount 前置条件）、compose 文件名自适应。
4. **不推送上游 `Shadowell/Alpha`**：只推自己的 fork `zdklrr/Alpha`（origin），
   第三方仓库不代改。
